## What Changes

npm announces that "the ability to publish new package versions directly with a granular access token will be removed in January 2027" (no exact day), bypass-2FA tokens included. A token can still **stage** versions (a stage-only token stages, deprecates and moves dist-tags, never publishes directly), and trusted publishing keeps direct publishing.

Relizy warns now: a direct publish to npmjs with a token prints one warning per run, linking here. `--no-safety-check` and [`publish.safetyCheck: false`](./../config/publish.md#safetycheck) silence it. It concerns npmjs only, never another registry, trusted publishing nor a local login.

## Choose a Path

| Path                                      | For                                                  | Human gate | Unattended  |
| ----------------------------------------- | ---------------------------------------------------- | ---------- | ----------- |
| [Trusted publishing](#trusted-publishing) | A release from GitHub Actions, GitLab CI or CircleCI | No         | Yes         |
| [A stage-only token](#a-stage-only-token) | A CI that cannot use trusted publishing              | Yes        | Stages only |
| [Local publishes](#local-publishes)       | A project released from a maintainer's machine       | Your 2FA   | No          |

## Trusted Publishing

The way for a CI: no secret to store, and it keeps publishing directly. See [Trusted publishing](./trusted-publishing.md).

1. **Workflow**: give the job its ID token (`id-token: write` on GitHub, `NPM_ID_TOKEN` on GitLab and CircleCI). The workflows generated by [`relizy init`](./../cli/init.md) already do. The job needs npm 11.5.1 or later: the generated workflows, the action and the component update npm when it is older than 11.15.0.
2. **npm**: run [`relizy trust`](./../cli/trust.md) once, from your machine, with your 2FA. It creates the trusted publisher of every package from the workflow. A package that is not on npm yet needs its first version published by hand first.
3. **Forge**: remove the `NPM_TOKEN` secret (GitHub) or variable (GitLab) once a release published with trusted publishing, or keep it for the first publish of new packages. An empty secret means no token.
4. **Config**: nothing to change. Add [`publish.staged`](./../config/publish.md#staged) if you want a human approval on top.

Relizy checks the setup before the bump, see [What Relizy Checks](./trusted-publishing.md#what-relizy-checks).

## A Stage-Only Token

When the CI cannot use trusted publishing (a self-hosted runner, GitLab self-managed), keep a token, and make it stage:

1. **npm**: create a granular access token that can only stage.
2. **Config**: turn staging on, [`publish.staged: true`](./../config/publish.md#staged), or by tag. A direct publish with this token fails with `E_STAGE_REQUIRED`, and Relizy tells the fix before asking any code.
3. **Approval**: a CI cannot approve. Run [`relizy stage approve --all`](./../cli/stage.md) after the release, or approve on npmjs.com, with one 2FA for all the versions.

See [Staged publishing](./staged-publishing.md).

## Local Publishes

A project released from a maintainer's machine publishes with their npm login and their 2FA, which a token never replaced: run `relizy release` locally, with `npm login`. Relizy asks the one-time password when npm requires it. Add `publish.staged` to approve all the versions at the end with one code.

## New Packages

Trusted publishing cannot create a package, and a package staged for the first time gets a placeholder `0.0.0-stage`. Publish the first version of a new package from your machine (`npm login`), then run `relizy trust`. A token can still publish a first version until January 2027, or stage it.

## Check Before the Deadline

- `relizy release --dry-run --log-level debug` in the CI shows the warnings and the auth mode, without publishing.
- `relizy trust --dry-run` lists what it would set up.
- The `publish_auth` output of a run that staged tells `oidc`, `token` or `npmrc`: see [the outputs](./staged-publishing.md#releases-from-a-ci).
