# CLAUDE.md

`@relizy/core`: the generic building blocks of relizy, published on its own and consumed by other projects (see the root `CLAUDE.md` for the compatibility rule).

- Only code relizy itself uses; a function that needs the resolved config or the CLI output of relizy stays in `packages/relizy`, its adapter passes plain parameters
- Reports go through an optional `CoreLogger` parameter, never a logger import; stdout is never written
- `src/index.ts` lists every export, `src/__tests__/index.spec.ts` guards the list
- Every export has a JSDoc (description, `@param`, `@returns`, `@example`): the `core/*` pages of the MCP server of relizy are generated from `index.ts` and these comments, and `knowledge.spec.ts` of relizy fails on an export without description or a function with undocumented parameters; a new export also needs its domain in `packages/relizy/src/mcp/knowledge/core-api.ts`
- Tests that mock a function called inside core must target its file by path (`vi.mock('../../../../core/src/git-refs')` from relizy), since the calls inside core do not go through the `@relizy/core` entry

## Modules

- **Git execution** (`git-exec.ts`): git only runs through `runGitSync`, `runGit` and their `try*` variants, `execFile` without shell, the arguments as an array, never a command string
- **Git cache** (`git-cache.ts`): `cachedGitRead()` caches the reads (branch, tags, commit ranges) only inside `withGitCache()`, and always runs git outside it; cached: `getCurrentGitBranch()`, `getFirstCommit()`, `tagExists()`, `isAncestor()`, `listTags()`, `getGitDiff()` (each caller gets a copy of the commits). A git write changing HEAD, a branch or a tag must call `clearGitCache()`; a check done once per run goes through `oncePerRun()`, never a module-level cache, since one process can run several releases
- **Commits** (`commits.ts`, `git-refs.ts`, `package-commits.ts`): `getGitDiff()` reads the commits and `parseCommits()` parses them, ported from changelogen 0.6.2 without behavior change (a fix goes in a separate commit; cases in `commits.spec.ts`). A commit belongs to a package when a file of its `--name-status` list is under the package directory (`isCommitInPackage()`), see `getPackageCommits()`
- **Catalogs** (`catalogs.ts`): a commit changing an entry of a catalog (`pnpm-workspace.yaml`, `.yarnrc.yml`, bun's root `package.json`) belongs to the packages referencing this entry with `catalog:` in any dependency field (their `package.json` at the commit); the catalogs before and after the commits are read at once (`git cat-file --batch`)
- **Moved packages** (`moved-packages.ts`): `getPreviousPackagePaths()` adds the former directories of a package so the commits made before a move keep counting. Moves are detected in the raw commits of the range (`getDetectedPackageMoves()`: a renamed `package.json`, as is for `R100`, for an inexact rename only when the package keeps its `name`, skipped when a package lives in the old directory again) or given (`movedPackages`, applied as is), followed through chains, and applied to the package commits, the root filter (`resolveReleasedPackagePaths()`) and the first commit of a new package (`getFirstPackageCommitHash()`, `git log --follow`)
- **Dependencies and peers** (`dependencies.ts`, `peers.ts`): `expandPackagesToBumpWithDependents()` finds the workspace dependents, transitive ones included; `getOutOfRangePeers()` and `getOutOfRangeDependencies()` check the published range (computed from the `workspace:` specifier and the version before the bump) against the new version of the dependency as npm does (no `includePrerelease`: `^6.19.1` rejects `6.20.0-beta.0`), a specifier that is not a semver range counting as out of range for dependencies; `isBreakingVersionChange()` is "not accepted by `^oldVersion`"
- **Tags** (`tags.ts`): `findVersionCommit()` finds the commit that set the current version of a package without a tag of it (through its moves), named after its tag; a package created with this version is `NEW_PACKAGE_MARKER`
- **Changelog** (`changelog.ts`, `markdown.ts`): `resolveChangelogRange()` gives the refs `git log` reads and the names shown (the release tag does not exist yet), `renderChangelog()` assembles title, compare link, sections and contributors; writing `CHANGELOG.md` and the hooks stay in relizy
